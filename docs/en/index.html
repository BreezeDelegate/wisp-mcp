Guided onboarding

From zero to your first diagnostic.

The flow deliberately separates WISP access, MCP installation and the AI connection. A failure in one layer does not force you to rebuild the others.

STEP 01

Confirm that your host uses WISP

WISP panels can be white-labelled. Compare your interface with the screenshot below or ask support: “Does my server use WISP, and can I create a WISP Client API token?”

Yes? Continue. No? Wisp MCP is not the right connector for that panel.
STEP 02

Prepare ChatGPT

Sign in to ChatGPT and choose the most capable model available. If GPT-5.6 Sol appears in your model picker, use it for complex coding and administration tasks.

This site receives no access to your OpenAI account. Model verification deliberately stays inside ChatGPT.
STEP 03

Connect GitHub if you want durable project memory

For a server maintained in GitHub, use a private repository and keep at least an AGENTS.md, roadmap and handoff there. The AI can resume from explicit rules and decisions instead of guessing.

Boundary: Git stores project memory; Wisp MCP provides panel access. Never store a WISP token in Git.
STEP 04

Install Wisp MCP and the ChatGPT tunnel

Connect to the VPS and run the installer. It creates a dedicated system user, keeps credentials outside Git and runs a diagnostic before reporting success.

curl -fsSL https://raw.githubusercontent.com/BreezeDelegate/wisp-mcp/main/install-vps.sh | sudo bash -s -- --with-openai
STEP 05

Start read-only

Validate the connection before granting mutation. Then enable only the capability families you actually need.

wisp-mcp doctor && wisp-mcp compatibility
STEP 06

Give the AI one simple operating rule

Ask it to inspect before changing, back up before risky operations, make the smallest necessary change, then re-check state and logs.

Capability control

The MCP server decides what the AI may do.

Switching AI clients should not silently broaden permissions. Mutation capabilities are explicit and destructive operations keep a separate gate.

Normal operation

  • Read state, resources, logs and files
  • Edit files with SHA-256 change detection
  • Run console commands when enabled
  • Restart or create backups when enabled

Destructive, deliberately separate

  • Delete files or backups
  • Restore a backup over live data
  • Delete databases or rotate credentials
  • Force-kill and equivalent operations
FAQ

The questions that most often block setup.

Is this tied to one hosting provider?

No. Wisp MCP targets the WISP Client API. If your host provides a WISP panel and a Client API token, the same connector applies.

Do I need to give ChatGPT unrestricted SSH access?

No. The point is to limit the AI to the WISP surface and the MCP capabilities you explicitly enable.

Is GitHub required?

No. GitHub is useful for preserving code, rules, roadmap and handoff. WISP connectivity works independently.

Why not enable every permission immediately?

Unused permissions increase the impact of mistakes. Start read-only, then open only what the task needs.
